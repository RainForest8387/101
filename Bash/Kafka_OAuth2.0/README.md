# Kafka + OAuth 2.0 («Фактор ЕСБ») на ALT Linux для ЗОКИИ

## Три вывода за 30 секунд

1. **Брокера Kafka в репозиториях ALT Linux нет** — ни в Sisyphus, ни в p10/p11. Есть только клиентские библиотеки (`librdkafka`, python-клиенты) и JDK. Брокер придётся брать tarball'ом со своей RPM-сборкой либо через Arenadata Streaming (в реестре российского ПО, сертификация ФСТЭК заявлена как идущая).
2. **OAuth 2.0 в Kafka 4.x работает штатно и без сторонних библиотек** — SASL/OAUTHBEARER + JWKS-валидация встроены. Ничего доустанавливать в ОС не нужно; `jose4j` идёт в составе дистрибутива Kafka.
3. **Про «Фактор ЕСБ» публичной информации нет**, поэтому подготовлен чек-лист требований к провайдеру и скрипт, который проверяет их по реальным endpoint'ам за 5 минут — до того, как разворачивать Kafka.

## Стенд

```
stand/
├── mock-idp.py      локальный OAuth 2.0 провайдер (RS256, JWKS, client_credentials, jwt-bearer)
├── setup-stand.sh   развернуть Kafka 4.x KRaft + TLS + OAUTHBEARER на ALT Linux
└── test-oauth.sh    8 шагов проверки — от discovery до produce/consume
```

```bash
sudo ./stand/setup-stand.sh install
./stand/setup-stand.sh start
./stand/test-oauth.sh
```

Смысл стенда: сначала убедиться, что схема Kafka + OAUTHBEARER рабочая, на заведомо корректном mock-провайдере. Потом заменить его на «Фактор ЕСБ» — и любая возникшая проблема будет однозначно на стороне ЕСБ, а не в конфигурации Kafka.

## Что уже проверено

- `mock-idp.py` запущен, проверены discovery, JWKS, выдача токена по `client_credentials` (Basic и form-post), отказ при неверном секрете (401), валидность RS256-подписи ключом из JWKS — по HTTP и по HTTPS.
- `test-oauth.sh` прогнан против mock-провайдера: шаги 1–5 проходят, разбор claim'ов и проверка подписи работают.
- Синтаксис всех скриптов проверен (`bash -n`, `py_compile`).
- Шаги 6–8 (реальный брокер) в песочнице не проверялись — доступ к `downloads.apache.org` закрыт; их нужно прогнать у вас на стенде.

## Первые шаги

1. Отправить владельцу «Фактор ЕСБ» блокирующие требования и вопросы из `03-factor-esb-requirements.md`.
2. Пока идёт согласование — поднять стенд на mock-IdP и убедиться, что Kafka настраивается.
3. Параллельно решить вопрос поставки брокера (собственный RPM vs Arenadata) и JVM (`java-17-openjdk` vs Axiom JDK Certified) — это, скорее всего, будет самым долгим пунктом.
